# Research

- **Decision**: Canonical user config, not another secret store. **Rationale**: tagged Neko1.9.5 project.ts/config.ts define profile-scoped credentials and atomic writes; host secureSecretStore is explicitly false. **Rejected**: plugin-store/localStorage, invented encryption claims, Core changes/releases.
- **Decision**: Offline save is unverified; actual Send verifies. **Rationale**: no second provider client, hidden model work/billing or catalog-as-authentication claim. **Rejected**: untracked agent subprocess/direct HTTP engine.
- **Decision**: Main-only typed IPC and private atomic files. **Rationale**: fail closed on malformed input/config without broad filesystem authority. windows-sys0.61.2 source confirms ConvertStringSecurityDescriptorToSecurityDescriptorW, SetFileSecurityW and LocalFree; Unix uses mode0600. **Rejected**: truncating writes, broad inherited permissions.
- **Decision**: Inherit builtin preset capabilities. **Rationale**: canonical `zai` is Coding Plan/Anthropic; `zai-openai` is pay-per-call and forbidden here. Custom compatible endpoints use independent coherent profile bindings.
- Sources: tagged Neko1.9.5 home.ts/project.ts/config.ts, current Wiii provider.rs, ProjectHome, NekoChillApp and host.ts. No unresolved clarification; no network call needed to render/save.
- Review correction: Core1.9.5 `setActiveProfile` can keep an existing profile key while replacing its endpoint from legacy globals. Wiii deliberately refuses mixed legacy/scoped connection records instead of copying that unsafe behavior; no data is rewritten on refusal. Core's provider checks `isLocalEndpoint`, not `auth:none`, before permitting an empty key; status/save follow that boundary. A failed strict setup read does not block Core's existing read-compatible configurations.
